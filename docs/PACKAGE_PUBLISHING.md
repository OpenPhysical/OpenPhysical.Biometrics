# Biometrics package publishing

The `Publish immutable DEV NuGet packages` workflow is manual. It checks out a full source commit with Git LFS, requires a clean tree, builds and records both macOS camera native RIDs on macOS runners, and collects those artifacts in the same workflow run. It packs the frozen `OpenPhysical.Biometrics.TestFixtures` beta.3 package into a local test feed, restores, builds, and runs the complete Biometrics solution, and restores the CSharpier tool manifest before formatting checks. Package versions come from their source projects, including `OpenPhysical.Biometrics.Packages` `4.0.0-dev.20261115.6` and camera `4.0.0-dev.20261115.2`.

The camera native artifacts are tied to the exact source commit and hashes for every Objective-C header/source and `build.sh`. The record also captures SDK/compiler versions, Mach-O architecture, file type, linked libraries, and binary hash. Before packing, verification requires both `osx-arm64` and `osx-x64`, checks each Mach-O CPU type and source/binary hash, and rejects stale or extra RIDs. Camera packing includes both native assets and then inspects the `.nupkg` entries against the verified per-RID records. The earlier local `Camera` `.1` package was arm64-only; `.2` is the first package version configured for the complete macOS native closure and has not been published.

Local integration evidence for the current change used Xcode SDK `27.0` and Apple Clang `21.0.0`: `osx-arm64` SHA-256 `d1e50d9ff86040bd8928efba5b0561a750ce0fb7c30db55dafd97419a9cbf85f` and `osx-x64` SHA-256 `aa5123ff272a0c502654d58cc15d744915cafd7ad567521c65362c0021bfa322`. The 14-package local candidate manifest has SHA-256 `9ddca74e76ff1d98f23a125e40482249a64ed9d3393b92ffba4205c6af9c59dd`; its Camera `.2` archive has SHA-256 `6ac652ace0af2f87b5c8d5085b5d216dc29cd6f9d80a65a4cc5b143cacc430cd` and contains both exact native assets. That package was added to the local bootstrap feed only because the version was absent there; no existing artifact was replaced. These checks used a dirty worktree at `cc7ef497d8047f45dae097a50203f2a92fac75fd`; source-file hashes are recorded with the local candidate artifacts, but this is not final source-commit release evidence. The publisher must recreate and validate the complete closure from its clean final commit. No camera hardware qualification is implied.

The fixture package stays in the local test feed and is excluded from `scripts/nuget-package-projects.json`. It contains only test data and helper content and has no consumer outside this repository. The publisher does not publish test fixtures.

The publisher records each `.nupkg` hash and size, every package entry hash, source commit, and native/model assets in `artifacts/package-manifest.json`. Before pushing, it checks GitHub Packages for every package ID/version, including deleted versions. Existing versions stop the batch. Push does not use skip-duplicate or overwrite a version. The package candidate and manifest are retained as a workflow artifact for review.

The workflow uses its repository `GITHUB_TOKEN` with `packages: write`. An OpenPhysical owner must grant `packages: read` to each consuming repository in package access settings. Bio packages are consumed by OpenPhysical.Net, Enrollment Studio, Issuer Studio, Issuance Server, and Directory. Gp4Net also needs read access from this repository. Those grants have not been confirmed. A DEV package manifest is build provenance, not production qualification.
